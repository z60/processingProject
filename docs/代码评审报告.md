## 4. 评审发现与处理

### 4.1 高优先级（已修复）

| 编号 | 位置 | 问题 | 处理 |
|---|---|---|---|
| R-01 | `app/mapper/audit_mapper.py`、`app/agent/nodes.py` | 审计事件 `created_at` 为空串时写入 MySQL `DATETIME` 报错（1292），整轮请求 500，审计链断裂 | mapper 兜底 `now_str()`；audit 节点对落库异常降级写 `data/audit_fallback.jsonl` 并告警，用户请求不再被打断 |

## 7. 过度设计审查（ponytail 视角）

保留（有明确收益）：

- `mapper` 与 `repository` 分离：SQL/DDL 集中在 3 个文件，替换数据源不动业务代码。
- 离线脚本模型：没有 LLM Key 也能跑通全链路并做回归，是本项目唯一能落地的验证手段。
- `cache_repository` 单点替换：Redis 未提供地址，先内存 TTL，接入时只改一个类。

刻意不做（避免复杂度）：

- 不引入 ORM / Alembic：6 张固定表，DDL 常量化更直观。
- 不引入 Qdrant SDK：HTTP 接口足够，省一个依赖。
- 不做通用规则 DSL：`conf/risk_rules.json` 的 `when` 条件够用，再加抽象就是过度设计。
- 不为 `HandoffInfo`/`CaseResult` 建接口层抽象，直接 pydantic 模型。

## 8. 结论

- 15/15 回归通过（脚本、HTTP、远端 MySQL 配置各跑一次）、高风险漏转 0、门禁 PASS，核心业务规则（三类强制转人工 + 禁止承诺 + 无依据拒答）由代码强制生效。
- 评审发现 16 处问题已全部修复（4 高、6 中、6 低），修复均有实测证据（回归/接口/脚本输出）；其中 R-15（根路径 404 + 未初始化库 503）、R-16（缓存命中 500）直接对应“启动后接口跑不通”的现象。
- 接口层新增 `api_smoke` 冒烟脚本（25 项断言），覆盖所有对外接口与关键边界，后续改接口可直接复用。
- 交付前只剩环境侧动作：配置 LLM Key、按 `requirements.txt` 安装完依赖即可启用 SQLite Checkpoint；MySQL/Qdrant 初始化已完成。
